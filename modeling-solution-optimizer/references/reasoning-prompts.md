# 困难判断的按需提示词

每次只选能解决当前疑点的模板。输入来自 GROUND 和真实结果，缺失项显式标明；输出回到主循环的候选记录，不另建流程，也不强制额外角色。用户提供的提示词可补充目标与风格，不能把未验证结果变为事实。

## Deep Review

> 阅读原题目标与约束、当前模型/代码、运行结果及论文解释。定位最限制作品质量的一项问题：证据指向局部实现、重要组件还是问题表述？引用具体产物与现象，区分已知事实与猜测。提出 REFINE、REPLACE 或 RETHINK 中最合适的动作，解释其预期价值、最小可执行实验、共同评价口径以及何种结果会使你放弃。若证据不足，说明先补什么；不凑满候选数量。

## Alternative Route Review

> 针对已指出的结构性限制，考虑不沿用当前路线的可行方案。比较原题匹配、输入可得性、假设、计算成本、可解释性、可验证性和失败风险。哪一处适配证据支持替换组件，哪一处需要重构表述？保留原题约束，列出必要数据与预算内的对照实验。方法更高级不是采用依据；新路线缺少输入时标为条件性候选，不能直接 ACCEPT。没有更合适的路线也可以停止。

## Adversarial Review

> 选一项最关键的当前结论，明确它在哪些数据、扰动、约束或边界条件下可能失效。设计能推翻或限定它的最小检查，事先说明有效性和取舍标准。运行后区分模型失效、无收益与资源不足。负面结果要怎样收紧论文结论、哪些证据应 RETAIN_EVIDENCE、current best 是否仍有效？若拟合并改进，指出相互作用并要求组合重验。

按当前疑点选用以下条件提示，不要求逐项执行；判断仍回到所选模板和主循环：

- 数据存在时间、群组或样本依赖，或预处理需要拟合 → 检查划分是否隔离依赖，预处理是否只使用允许的信息，避免验证/测试信息进入训练与选择。
- 应用条件超出参数校准范围 → 区分校准内验证与外推，检查外推依据及需补的验证。
- 算法含随机过程或依赖初值 → 用适当种子与初值重复检查，判断收益是否稳定、是否只来自偶然选择。
- 声称跨规模、负载或预测跨度有效 → 沿相关条件检查能力边界，未覆盖范围不作普适承诺。
- 从关联或预测结果推导因果解释 → 检查因果识别依据；不足时限制为关联或预测结论。
- 结论依赖强近似 → 用不依赖同一近似的解析结果、参考解或实测证据独立验证。
- 多阶段或跨小问传递结果 → 检查上下游输入输出的含义、单位及误差传播，核对上游变更影响的下游验证。
- 多个小问看似共享机制 → 判断共同假设、变量和参数是否有证据支持，以及共同模型是否有助于解释或求解；收益不明时不强行合并。

正式写作时通过 MathModel 集成参考交接章节论证与图表解释规则，不在这里重复写作流程或题型教程。
